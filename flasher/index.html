S3 Sentinel flasher

This page writes S3 Sentinel firmware to an ESP32-S3 board over USB, from your browser. It uses ESP Web Tools and the Web Serial API, so it works in Chrome or Edge on a desktop computer.

Experimental, uncertified firmware. Read the limitations before you rely on it.

Updating keeps your settings. Erasing does not.

This page writes the bootloader, the partition table and the application. It does not write the settings partition, so an update keeps the settings, the joined Wi-Fi network, and the FIDO credentials and PIN.

If the install dialog offers to erase the device and you choose erase, every saved value is removed: settings, Wi-Fi, FIDO credentials and PIN. Any site where you registered the security key will then stop accepting it. Sign in to those sites with another method first, then register the key again.

Flashing from this page does not burn any eFuses. The FIDO hardening step in the dashboard is separate and irreversible, and it runs only when you start it there.

Before you start

  • A desktop computer running Chrome or Edge. Firefox and Safari do not support Web Serial, and phone browsers do not either.
  • An ESP32-S3 board with 16 MB flash and 8 MB octal PSRAM, connected with a cable that carries data.
  • Nothing else using the board's serial port, such as a terminal program.

Put the board in download mode

The firmware on the board has no serial port of its own, so the board must start in ROM download mode before you connect. Use one of these:

  1. Hold the BOOT button.
  2. Tap RESET, or plug the board in while still holding BOOT.
  3. Release BOOT. The board is now in download mode, and it shows up as a serial port.

If the install dialog finds no port, repeat these steps.

Choose a build

Release build

The firmware to use. It is built from sdkconfig.defaults only, with developer endpoints off.

Three parts: bootloader at 0x0, partition table at 0x8000, application at 0x20000

This browser cannot flash from a web page. Use Chrome or Edge on a desktop computer. Web Serial needs a secure page. Open this page over HTTPS.

Development build (for developers)

A secondary build for developers, for test boards only. It enables the developer endpoints: the debug log endpoint /api/log, the vendor security-key commands 0x51 and 0x52, and download mode over HTTP without a BOOT hold. Do not use it on a device that holds credentials you need.

Three parts: bootloader at 0x0, partition table at 0x8000, application at 0x20000

This browser cannot flash from a web page. Use Chrome or Edge on a desktop computer. Web Serial needs a secure page. Open this page over HTTPS.

Erase option

The install dialog can erase the flash first. Leave erase off to keep settings, Wi-Fi, FIDO credentials and the PIN. Choose erase for a clean install, or when a release says a clean install is needed. Erasing clears the whole chip, including the core-dump partition.

After flashing

  1. The board restarts. Open http://192.168.7.1 in your browser while the board is connected over USB. The address works only over that USB network link.
  2. Set a Wi-Fi network if you want breathing estimates, and calibrate with the room empty if you want presence to work well.

A release build does not enter download mode when the dashboard asks it to, unless you hold BOOT for 3 seconds during the request. The other route is the hardware one: hold BOOT, tap RESET, release BOOT. The development build enters download mode at once when asked.

Status of this page

The firmware was tested on one board, on macOS. This page has not yet been checked on hardware. Other boards and host systems are untested. The source, the build steps and the known limits are in the repository.
